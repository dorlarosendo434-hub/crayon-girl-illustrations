# 构图模式与原创规则

## 基础结构类型

选择一种结构即可，不要混太多。

### Workflow 流程

适合：输入 -> 处理 -> 输出，内容生产，AI 工作流，自动化链路。

画法：左侧输入，中间由蜡笔女孩整理、连接或推动一个低科技装置，右侧输出，橙色箭头表达主流向。

### 系统局部

适合：信息来源、过滤器、数据库、渲染器、agent 系统局部。

画法：只画 3-5 个核心模块，蜡笔女孩参与其中一个关键动作。

### 前后对比

适合：混乱/有序，手动/自动，分散/收拢，焦虑/稳定。

画法：左混乱，右稳定，中间橙色箭头。角色可以在中间完成整理动作。

### 角色状态

适合：用户痛点、创作者状态、工具太多、信息焦虑、卡住到跑起来。

画法：2-4 个小状态，每个状态一个短标注。保持角色识别锚点一致。

### 概念隐喻

适合：内容工厂、信息仓库、脑内抽屉、工作流机器、自动日报。

画法：一个大的温暖物件或低科技装置，少量输入，一个输出。要有记忆点。

### 方法分层

适合：方法论框架、系统层级、能力栈、内容系统分层。

画法：一层层盒子、抽屉、书页或布料，不要正式金字塔；蜡笔女孩在旁边搭建、标记或收纳。

### 地图路线

适合：从想法到上线、用户路径、内容承接路径、学习路线。

画法：一条弯曲路径，少量节点，蜡笔女孩牵线、贴标签、背包行走或在路牌旁做标记。

### 小漫画分镜

适合：失败到成功、真实过程、吐槽、使用前后变化。

画法：2-4 个小场景，每格只表达一个动作。不要画成儿童绘本连续故事。

### 新手解释图

适合：解释“是什么、怎么工作、由什么组成、能否复用、能否修改”等基础概念。

画法：

1. 用一个具体主物件代表概念，例如工具箱、工作台、背包、抽屉或小机器。
2. 让读者看到主物件里面有什么，只保留 3-5 个关键组成部分。
3. 用一条清楚的输入 -> 处理 -> 输出路径表现它如何工作。
4. 把“复用、修改、检查”等补充能力放在主场景旁边，用物理动作表达。
5. 蜡笔女孩必须打开、替换、操作或检查主物件，不能只负责指向标签。

标签可以比普通正文配图略多，但要使用明确名词和动词。避免只写“更简单、很方便、可使用”这类没有信息量的词。

判断标准：看完后，新手应该能用一句话复述“它是什么”和“它如何工作”，而不只是知道它有几个优点。

## 原创隐喻生成法

每次都从当前文章重新发明隐喻，不能照搬旧图或参考图。

### 三步

1. 把抽象概念换成一个物理动作：卡住、漏掉、变重、分拣、沉淀、开门、折叠、拆包、回流、装袋、贴签。
2. 把系统结构换成一个低科技物件：纸箱、抽屉、手账、路标、小邮筒、秤、线团、布袋、便签墙、旧机器、书页、地图。
3. 让蜡笔女孩承担动作：不是站旁边，而是理线、收纳、贴标签、推机器、修补连接、背包转运、圈重点、给路径打结或解结。

### 可用物件池

- 纸箱、抽屉、旧机器、手账、便签、邮筒、门、梯子、线团、路标、布袋、背包、书页、地图、打孔器、晾衣绳、小桌子。
- 用时只选 1-2 个，不要堆满。

### 蜡笔女孩动作池

- 整理、牵、背、装、贴、圈、捞、推、接、修、剪、折、标记、收纳、递交、打开、合上。
- 动作要服务核心意思，不要为了可爱而可爱。

## 反复刻规则

不要默认寻找或复刻原版案例图。新 skill 的主要校准来自 `assets/ip-reference/` 的角色锚点。

除非用户明确说“照这张 / 复刻这个构图 / 用这个案例改”，否则不要直接复用这些构图：

- 参考图里的正面站姿头像。
- 参考图里的蓝底星星、问号、圈圈涂鸦组合。
- 传送带两个断点。
- 内容机器里拉判断杆。
- 角色变漏斗分拣流量/信任/转化。
- 切素材鱼。
- 牵承接路径。
- 拉三层信息源。
- 盖章话术工具箱。
- 举牌看常见坑路径。

同类主题也要换新隐喻。例如“承接路径”不一定画路线，可以画蜡笔女孩把一叠便签装进斜挎包再递给下一扇门；“一鱼多吃”不一定画鱼，可以画她把一个纸团折成几种用途。
